## What I Learned

- A vague prompt produces working but inconsistent code — quality drops in accessibility, error handling, and edge cases.
- A detailed, structured prompt (with clear constraints, expected behavior, and review criteria) consistently produces cleaner, more maintainable output.
- Separating **planning** from **implementation** in the prompt itself reduces back-and-forth corrections significantly.
- AI-generated code still needs to be reviewed line-by-line — it can look correct while missing accessibility or edge-case handling.
- Documenting the workflow (`WORKFLOW.md`) makes it much easier to repeat a good process instead of reinventing it every time.
- Writing reusable project rules (`CLAUDE.md`) upfront saves time across future assignments, since the AI assistant follows the same conventions automatically.

---

## What I Enjoyed Most

- Seeing the side-by-side difference between the vague-prompt and detailed-prompt versions of the same feature — it made the impact of prompting quality very concrete instead of theoretical.
- Building the first version of a personal "AI working rules" file (`CLAUDE.md`) that I could reuse and refine in later weeks.
- The comparison exercise felt less like "using AI" and more like learning how to **direct** AI properly — that shift was the most valuable part of the week.
